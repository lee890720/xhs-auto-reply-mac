# 小红书 / X 评论自动回复系统

本地运行的评论自动回复工具，支持两个平台，各自独立启停：

- **小红书**：Playwright 驱动浏览器采集评论
- **X（推特）**：官方 API 拉取 @ 我的推文，并列出新关注者供人工决定是否回关（见 [X 渠道](#x推特渠道)）

回复都由大模型 API 生成，人工审核放行后自动发送。为在 Mac mini 上长期无人值守运行而设计。

```
        ┌──────────────────────────────┐
        │  菜单栏 App                    │   书 ● 3
        │  状态 / 启停 / 打开控制台        │
        └───────────┬──────────────────┘
                    │ HTTP · launchctl
        ┌───────────▼──────────────────┐
        │  xhsd 守护进程（launchd 托管）  │   开机自启 · 崩溃自愈 · 单实例锁
        │  ┌────────────────────────┐  │
        │  │ FastAPI   控制台 + API  │  │
        │  │ Scheduler 轮询/限流/静默 │  │
        │  │ Collector Playwright   │  │   小红书
        │  │ XEngine   X 官方 API    │──┼──→ api.x.com
        │  │ Generator  人设 + 清洗   │──┼──→ DeepSeek / 百炼 / TokenHub
        │  │ SQLite    消息/回复/配置 │  │
        │  └────────────────────────┘  │
        └──────────────────────────────┘
```

## 安装

```bash
bash scripts/install.sh
```

脚本会创建虚拟环境、下载 Chromium、注册 launchd 开机自启、在 `~/Applications` 生成菜单栏 App，
然后自动打开控制台。全程约 15 分钟，绝大部分时间在下载浏览器内核。

> **在新机器上首次部署，请看 [DEPLOY.md](DEPLOY.md)。**
> 无人值守运行还需要配置自动登录和禁止休眠——不做的话重启后系统不会自己恢复，
> 而且不会有任何提示。

## 首次配置

1. **填模型 API** — 控制台「设置 → 模型 API」，选服务商、粘贴 API Key，点「测试连接」确认通
2. **登录小红书** — 点菜单栏图标 →「扫码登录小红书」，在弹出的浏览器窗口扫码
3. **开始监控** — 点菜单栏 →「开始小红书监控」，或控制台顶栏「小红书」旁的「启动」

两个平台默认都不运行，也都不随守护进程自动启动；要开机自动运行，在「设置 → 系统」里分别勾选。
X 的配置见下面的 [X 渠道](#x推特渠道)。

默认是**审核模式**：只生成草稿，你在控制台点「批准并发送」后才会真的发出去。
建议先这样跑一周，确认回复质量后再切全自动。

## 支持的模型服务商

| 服务商 | Base URL | 说明 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | 性价比高，中文口语自然，推荐 `deepseek-chat` |
| 阿里百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 国内延迟低，`qwen-plus` / `qwen-turbo` |
| TokenHub | 需手动填写 | 填控制台给出的 OpenAI 兼容端点 |
| 自定义 | 需手动填写 | 任何 `/chat/completions` 兼容服务，含本地 Ollama |

切换服务商只需改配置，不用动代码。

## 控制台

默认地址 `http://127.0.0.1:8787`，只监听本机。

- **概览** — 今日发送量、待审数、成功率、14 天趋势、互动最多的用户
- **审核队列** — 逐条查看评论原文和 AI 草稿，可直接编辑后批准，或重新生成、拒绝。
  每条评论上方显示它所属的笔记，这样才判断得出回复对不对题
- **设置** — 模型 API、回复人设、发送节奏、敏感词，改完立即生效，不用重启
- **日志** — 结构化运行日志

## 笔记上下文

评论几乎都是接着笔记说的。笔记正文是「操场寻跑步搭子」，评论「约起来，我可以」
才有意义；只看评论本身，模型只能回一句放之四海皆可的空话。

小红书通知页的 DOM 里没有笔记链接（只有封面图和用户主页），所以 `note_id` 是从
通知页自己请求的 `/api/sns/web/v1/you/mentions` 响应里取的，再用它打开笔记详情页，
读 `__INITIAL_STATE__` 拿标题、正文和话题标签。

抓取结果按 `note_id` 缓存在 `notes` 表：**一篇笔记只抓一次**，同一篇下面几十条
评论共享同一份缓存。只有抓取真正失败（笔记被删、网络抖动）才会在 6 小时后重试；
纯图片和视频笔记本来就没有正文，不会被反复重试。

拿不到笔记内容时，prompt 里会如实说明这一点，让模型只针对评论本身简短回应，
而不是脑补一个不存在的话题。想更严格可以打开 `require_note_context`，
让缺少上下文的草稿一律转人工。

> 图片承载主要信息的笔记（正文为空）仍然只能拿到很有限的上下文，
> 这是目前的固有局限。

## 回复状态流转

```
采集到评论 ──→ 生成草稿 ──┬─→ 审核模式 ─→ 待审核 ─┬─→ 批准 ─→ 待发送 ─→ 已发送
                        │                    └─→ 拒绝
                        └─→ 全自动 ────────────────→ 待发送 ─→ 已发送
                                                              └─→ 失败（重试 3 次）

命中敏感词 ──→ 敏感词拦截（不调用模型，等你手动处理）
模型判断不宜回复 ──→ 同样进拦截队列，等你手动处理
```

## X（推特）渠道

和小红书并列的第二个渠道，走 X 官方 API v2，不开浏览器。只开 X 时不会启动 Chromium。

| 功能 | 怎么做 |
|---|---|
| 别人 @ 我（包括回复我的推文） | 拉取 → 生成草稿 → 审核队列 → 批准后发送 |
| 别人关注我 | 列进「X 新关注者」页，**你逐个点「回关」才会执行** |

### 写死在代码里的规则

依据 X 开发者指南（docs.x.com/developer-guidelines），不做成开关：

- **只回复 @ 了你的推文**，代码里没有任何搜索接口。按关键词自动回复陌生人是指南点名的违规。
- **每条推文最多回一次**（指纹 `x:<推文ID>` 去重），**每人每日上限**默认 3 条。
  @ 超过 5 个账号的视为群发、只有 @ 没有内容的，都直接进拦截队列。
- **不自动回关。** 指南的场景表把"自动回关所有关注者"归为批量/激进关注。所以新关注者只进列表，
  没有「全部回关」按钮；点了「回关」的按 20–90 秒随机间隔执行，每日上限默认 50。
- **AI 回复要先获得 X 批准。** 指南要求用 AI 生成并发布回复的应用，事先通过
  [Policy Support 表单](https://help.x.com/forms/platform) 申请。设置里没勾选「已获得 X 批准」就不能切全自动。
  全自动运行的账号还要在资料页开启「Automated」标签，并在简介里写明是机器人以及谁在运营。
- **不冒充真人。** X 的人设里，被问"是不是机器人"一律输出 `[SKIP]` 转人工。

### 配置步骤

1. 在 [developer.x.com](https://developer.x.com/en/portal/dashboard) 建 App，把权限设为 **Read and Write**，
   **改完权限之后**再生成 Access Token and Secret。之前生成的令牌仍然是只读的，发送时会 403。
2. 控制台「设置 → X 账号」填 4 个值，点「测试连接」。测试只验证能读；写权限要等第一次发送才知道。
3. 顶栏「X」旁边点「启动」。**首次运行只记起点**：之前的 @ 不会补回复，现有关注者也不会进待回关列表。
4. 审核队列可以按平台筛选。X 的草稿下面有字数计数：上限 280，中文一个字算 2。

认证用 OAuth 1.0a 用户令牌：只服务自己一个账号时不需要回调地址，令牌也不会过期。

### 费用

X API 按量计费，没有免费档。钱花在三处，代码都按省钱的方式写：

- **读 @**：每轮带 `since_id`，只拉上次之后的新推文；被回复的那条推文通过 expansions 一起带回，不额外请求。
  被「批准」或「回关」唤醒时只处理队列，不额外拉 @。
- **发回复**：每条一次请求。
- **读关注者**：每次默认只取 5 人，碰到见过的人就停，全是新人才往后翻页。

具体单价以开发者后台显示为准。

### 出错时

| 情况 | 处理 |
|---|---|
| 401 密钥失效 | X 引擎停止，控制台顶部横幅提示，菜单栏显示「!」 |
| 402 额度用完 | 暂停 1 小时后再试 |
| 403 / 404（对方限制回复、删了推文、屏蔽了你） | 这一条判失败，不重试 |
| 429 频率限制 | 暂停到 `x-rate-limit-reset` 给出的时间 |

### 依赖的假设

- 新关注者检测依赖关注者接口「最近关注的排在最前」。X 没有书面承诺这个顺序；如果顺序变了，
  后果是新关注者被漏检，不会误关注任何人。
- 别人回复你的推文时，X 会自动在正文前加上 @你，所以这类回复也会出现在 mentions 里。

## 什么评论不会自动回复

敏感词表列不完所有不该回的情况，而强迫模型对一句辱骂编出得体回复，
结果只会是「哈哈，欢迎你呀」这种自证愚蠢的答复。所以人设里给了模型弃答的权利，
它输出 `[SKIP]` 时这条评论转人工，不自动发送：

- 人身攻击、辱骂、脏话
- 用贬称或侮辱性标签指代你或某个群体的，包括包装成反问的
- 大段立场宣示、明显来引战的（哪怕立场跟你一致也不附和，替账号站队有风险）
- 质疑或抗议你是机器人的（「转人工」「你是不是AI」）—— 再热情寒暄等于当场自证
- 评论里只有 `[图片]` `[视频]` 这类模型看不到的内容，避免假装看过并评价
- 纯表情、纯 @ 别人、纯数字、短到看不出意思的

在真实评论区里这个比例可能不低（实测 22 条里 12 条弃答）。这不是模型过度保守，
而是评论区的真实构成 —— 弃答的都进拦截队列，你可以在控制台逐条处理。

## 回复里的禁用词

**设置 → 安全策略 → 回复里的禁用词**。这一项针对**生成出来的回复**，
不是评论内容。命中就重新生成一次（并告知模型哪个词违规），再命中转人工。

默认禁止在评论区提群（`拉群` `进群` `建群` `加群` `群里` `群聊`）。原则是
引导私信就够了，拉群的事等对方私信过来再说。

之所以要在代码里拦一道而不是只靠人设里写禁令：人设是概率约束。实测有一篇
笔记正文自己写着「有兴趣的评论区或私信我，拉群约球」，模型就会把这句原话
搬进回复；在人设里明令禁止之后，同一条评论重跑几次仍有一两次漏出来。
硬规则交给代码，才是确定的。

用整词而不是单个「群」字，是为了少误伤：「群体」「一群人」都不会命中。
但 `群里` 仍然会匹配到「人群里」「这群里」这种组合 —— 评论回复里极少这么说，
真命中了也只是多生成一次，不影响正确性。想更保守就把 `群里` 从列表里删掉，
`拉群` `进群` `建群` `加群` 已经覆盖了绝大多数说法。

## 防风控设计

| 机制 | 默认值 | 位置 |
|---|---|---|
| 轮询间隔 | 120 秒 | 设置 → 回复策略 |
| 每日发送上限 | 50 条 | 同上 |
| 发送间隔随机化 | 8–30 秒 | 同上 |
| 夜间静默 | 23:00–08:00 不动作 | 同上 |
| 打字节奏模拟 | 每字符 40–110ms 随机 | 代码内置 |
| 敏感词拦截 | 投诉/律师/医疗等 | 设置 → 安全策略 |

评论去重靠数据库唯一索引（消息指纹），进程重启不会重复回复同一条。

抓取笔记正文会多访问一次笔记详情页，但**每篇笔记只抓一次**并永久缓存，
不构成额外的高频访问。一篇笔记下几十条评论共享同一份缓存。

## 常见问题

**点了 App 图标什么都没发生** — 先看屏幕右上角菜单栏，图标可能已经在那儿了（这个 App 不占 Dock）。
如果确实没有，看 `logs/menubar.log`。已知两个坑都已规避，改代码时注意别踩回去：

- `rumps.App(name=...)` 的 name 必须是 ASCII，用中文会静默不创建菜单栏项
- launcher 脚本必须后台启动 python 再自己退出，用 `exec` 会让 python 成为
  bundle 主进程，这种情况下 WindowServer 不给它创建菜单栏项

**菜单栏图标显示 `书 ✕`** — 守护进程没在跑。点「重启守护进程」，或看 `logs/daemon.err.log`。

**一直提示需要扫码** — 小红书登录态过期了。点「扫码登录小红书」，扫完回控制台点「重新检测」。
待登录状态下引擎每 5 轮会自己重检一次，误判或登录态自行恢复时不用管也会继续。

**点启动报「Chromium 浏览器内核未安装」** — 内核装在 `~/Library/Caches/`，
被清理工具删掉过。重装即可，数据和登录态都不受影响：
`.venv/bin/python -m playwright install chromium`

**回复没发出去** — 检查是不是还在审核模式（草稿要手动批准）、是否到了每日上限、是否处于静默时段。这三项在概览页都能看到。

**很多评论一条都没回** — 看「敏感词拦截」筛选。模型判断不宜回复的评论也会进这个
队列（辱骂、引战、质疑你是机器人、只有 `[图片]` 的评论等）。这个比例可能不低，
实测有争议内容的账号 22 条里 12 条弃答。详见「什么评论不会自动回复」。

**回复开始泛泛而谈、跑题** — 笔记上下文没拿到。日志里搜
`未能对上 mentions 接口数据` 或 `抓取笔记`，说明小红书改了接口或详情页结构。
审核队列里每条评论上方会标出它所属的笔记，没取到会明确写出来。

**升级后回复语气没变** — 配置存数据库，代码里的默认人设不会覆盖你已保存的那份。
见 [DEPLOY.md 第八节](DEPLOY.md) 的「更新代码后」。

**找不到页面元素** — 小红书改版了。`screenshots/` 里有失败现场，据此调整 `xhsd/collector.py` 里的选择器。

## 注意

- 自动化操作有被平台风控的风险，建议先用小号测试
- 涉及交易、医疗、法律的评论请人工回复，敏感词拦截默认就是这个用途；
  辱骂、引战、质疑是机器人一类的评论，模型也会主动弃答转人工
- 本工具仅供学习研究使用
